# Аудит репозитория от 15.09.2026

## Исходное состояние

- Корень смешивал приложение, 371 отслеживаемый Markdown-документ в двух каталогах, локальные DOCX/PDF/XLSX, изображения, инструменты и generated publish-каталоги.
- `.env` с рабочей конфигурацией отслеживался Git, хотя `.env.example` уже существовал.
- `ChecklistSeedData.cs` занимал около 884 КБ и содержал 1 386 записей данных в виде C#-литералов.
- README описывал устаревшую структуру и одновременно служил длинной эксплуатационной спецификацией.
- Правила размещения новых файлов и единый порядок проверки отсутствовали.
- `Program.cs` (около 41 КБ) и `wwwroot/css/site.css` (около 96 КБ) объединяют несколько функциональных областей.
- Два временных publish-каталога занимали примерно 1,56 ГБ вне уже выделенного `artifacts/`.

## Решения текущего этапа

- Введены явные корни `data/`, `docs/`, `scripts/`, `src/` и `tests/`.
- Runtime-база знаний и начальные данные отделены от кода.
- Подготовительные документы отделены от утверждённой базы знаний и не подключаются к runtime автоматически.
- Локальные бинарные материалы сгруппированы в `data/reference/` и исключены из Git/Docker context.
- `.env` оставлен на диске, исключён из индекса и заменён в контракте репозитория на `.env.example`.
- Generated publish-каталоги перемещены внутрь `artifacts/`.
- Созданы карта потоков, правила для агентов и поэтапный список технического долга.

## Риск, требующий решения владельца

Удаление `.env` из текущего индекса не удаляет его из старых commit. Если файл когда-либо содержал действующие токены или пароль БД, их следует ротировать. Переписывание Git-истории намеренно не выполнялось: это нарушает ссылки на существующие commit и требует отдельного согласованного окна.
