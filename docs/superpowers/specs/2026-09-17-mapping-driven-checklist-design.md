# Формирование чек-листа по mapping и реестру требований

## Цель

Карточка объекта является единственным источником фактов. Mapping определяет применимые критерии, а общий реестр — применимые требования. Исторический шаблон не определяет состав результата.

## Поток данных

1. Карточка хранит категорию НВОС, тип, регион, функциональные зоны, оборудование, особые зоны и экологические аспекты.
2. Для каждого критерия mapping сначала проверяются идентификационные ограничения: категория, регион и тип.
3. Затем проверяются содержательные признаки карточки: экологический аспект и связанные зоны, оборудование или особая зона. Известные совпадения включают критерий; отсутствие известных совпадений исключает его; незаполненные поля не блокируют процесс.
4. Реестр фильтруется пересечением с включёнными критериями, категорией НВОС и кодом региона для региональных требований.
5. Шаг 4 мастера показывает только включённые критерии и причины совпадения.
6. Шаг 5 показывает только найденные требования с уровнем, формулировкой и основанием. Состав чек-листа строится из этого набора без LLM-вызовов.

## Карточка объекта

Блок «Готовность карточки», подтверждение и требование заполнить все булевы признаки удаляются. Сервис всегда использует фактически заполненную информацию. Известные объекты предзаполняются из утверждённых карточек. Рядом с полями показывается значок `i` с текстом из документа «Всплывающие подсказки (Tooltips) для полей профиля объекта».

## Ограничения данных

- Ошибка исходного mapping `4.1` для лицензирования нормализуется как `4.10` и фиксируется в манифесте.
- Код `2.7`, отсутствующий в mapping, не может самостоятельно включить критерий; связь сохраняется в требованиях для аудита.
- Региональные коды: Пермский край — `59`, Удмуртская Республика — `18`, Кировская область — `43`.
- Неизвестные поля не блокируют подбор, но не создают совпадений.

## Проверка

Доменные тесты проверяют точное применение mapping, фильтрацию категории и региона, отсутствие выбора целого раздела и различие результатов для разных карточек. UI-проверка подтверждает отсутствие блока готовности, наличие подсказок и раздельные шаги критериев и требований.
