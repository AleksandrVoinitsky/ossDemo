# Экспорт сформированного чек-листа

## Цель

Заменить существующие технические выгрузки полноценными печатными документами PDF, DOCX и XLSX. Все три формата должны содержать одинаковые сведения сформированного чек-листа, соответствовать утверждённым формам уровня Общества и уровня филиала Общества и оставаться читаемыми при чёрно-белой печати.

Эталонами шапки и завершающего блока служат:

- `data/reference/templates/Форма чек-листа по проведению ИК ООС уровня Общества (Приложение А).pdf`;
- `data/reference/templates/Форма чек-листа по проведению ИК ООС уровня филиала Общества (Приложение Б).pdf`.

## Границы задачи

В задачу входят:

- сохранение типа и шапки выбранного шаблона в снимке сформированного чек-листа;
- единая подготовка данных для трёх экспортных форматов;
- нативная генерация PDF, DOCX и XLSX;
- чёрно-белое печатное оформление;
- сохранение существующих ссылок скачивания;
- автоматические структурные проверки и визуальная проверка файлов.

В задачу не входят новые обязательные поля мастера формирования, электронная подпись, редактирование реквизитов непосредственно перед скачиванием и хранение готовых файлов в базе данных.

## Выбор варианта шапки

Для чек-листа сохраняются снимки `scope` и `header` исходного шаблона в момент формирования. Последующее изменение шаблона не должно менять ранее сформированный чек-лист.

- `society` использует форму приложения А и формулировки уровня Общества.
- `branch` использует форму приложения Б и формулировки уровня филиала Общества.
- ИИ-чек-лист без связанного шаблона использует `branch`, поскольку он формируется для выбранного объекта или структурного подразделения.
- Для старых записей без снимка применяется совместимый резервный выбор: связанный системный шаблон, если он доступен, иначе `branch`.

Снимок должен быть частью `ChecklistDetails`, чтобы API и генераторы работали с одним самодостаточным представлением.

## Общая модель экспортного документа

Отдельный построитель преобразует `ChecklistDetails` в неизменяемую модель экспорта. Генераторы форматов не принимают решений о типе шапки и не переопределяют значения.

Модель содержит:

- тип формы: Общество или филиал;
- название формы и приложения;
- номер чек-листа;
- название сформированного чек-листа;
- проверяемый объект или структурное подразделение;
- период проверки;
- дату актуализации;
- статус;
- сведения об утверждении;
- сгруппированные по разделам пункты;
- данные завершающего блока.

Номер строится детерминированно из идентификатора чек-листа в коротком читаемом виде и не меняется между скачиваниями. Дата актуализации берётся из `UpdatedAt`. Для утверждённого документа имя `ApprovedBy` выводится в сведениях об утверждении; для черновика указывается, что документ не утверждён.

## Сопоставление реквизитов

| Реквизит формы | Источник | Поведение при отсутствии |
| --- | --- | --- |
| Номер чек-листа | Короткое представление `ChecklistDetails.Id` | Всегда доступен |
| Наименование | `ChecklistDetails.Name` | Используется стандартное название формы |
| Проверяемое подразделение или филиал | `ChecklistDetails.Facility` | Печатная линия |
| Дата начала | `InspectionStartedOn` | Печатная линия |
| Дата окончания | `InspectionFinishedOn` | Печатная линия |
| Дата актуализации | `UpdatedAt` | Всегда доступна |
| Утверждающее лицо | `ApprovedBy` | Для черновика — «Не утверждён» |
| Дата утверждения | `ApprovedAt` | Печатная линия |
| Приказ об утверждении | В текущей модели отсутствует | Печатная линия |
| Ответственное лицо | В текущей модели отсутствует | Печатная линия |
| Время начала и окончания | В текущей модели отсутствует | Печатные линии |
| Должность проверяющего | В текущей модели отсутствует | Печатная линия |

Неизвестные реквизиты не заполняются вымышленными значениями. В DOCX и XLSX они остаются редактируемыми, а в PDF пригодны для ручного заполнения после печати.

## Структура документа

Первая страница содержит обозначение приложения, заголовок формы, номер, название сформированного чек-листа и реквизиты проверки. Для формы уровня Общества дополнительно воспроизводится поле подразделения, ответственного за проведение контроля. Для формы уровня филиала используется формулировка об ответственном лице.

Основная таблица имеет шесть колонок:

1. номер по порядку;
2. наименование контролируемой позиции;
3. основание или наименование нормативного документа;
4. результат: да (1), нет (2), не применяется (0);
5. описание несоответствий;
6. примечание.

Раздел чек-листа выводится отдельной строкой, объединённой на всю ширину таблицы. Порядок пунктов сохраняется по `Position`. Значения берутся из `Title`, `Basis`, `Result`, `Nonconformity` и `Note` без потери текста. Технические поля `Origin` и `SourceLabel` в стандартную печатную форму не добавляются.

В конце формы уровня Общества выводится строка подписи проверяющего. В конце формы уровня филиала выводятся должность и ФИО, подпись и дата, как в приложении Б.

## Визуальный стандарт

Все форматы используют общий визуальный язык:

- лист A4, преимущественно книжная ориентация; XLSX может использовать альбомную ориентацию для сохранения читаемости таблицы;
- чёрный текст на белом фоне;
- тонкие чёрные или тёмно-серые границы;
- светло-серая заливка только у заголовка таблицы и строк разделов;
- без цветных статусов, логотипов, декоративных плашек и фоновых изображений;
- читаемый шрифт с кириллицей размером не менее 8 пунктов в таблице;
- перенос длинного текста и автоматическая высота строк;
- повтор заголовка таблицы на новых страницах;
- номер страницы в нижнем колонтитуле.

## PDF

PDF генерируется как настоящий документ с Unicode-шрифтом и кириллицей. Транслитерация удаляется. Таблица автоматически переносится между страницами; строка пункта не обрезается, заголовок повторяется. PDF должен открываться стандартными просмотрщиками и печататься на A4 без выхода за область печати.

## DOCX

DOCX создаётся средствами Open XML как редактируемый документ Word. Таблица остаётся нативной, шапка таблицы помечается как повторяемая, ширины колонок задаются явно, строки разделов объединяются. Печатные линии и незаполненные реквизиты остаются редактируемым текстом. Документ не должен зависеть от установленных шаблонов Word.

## XLSX

XLSX создаётся средствами Open XML как нативная книга Excel с двумя представлениями одних данных:

- лист `Чек-лист` воспроизводит стандартную печатную форму с шапкой, строками разделов, областью печати и повтором заголовка таблицы;
- лист `Данные` содержит плоскую таблицу, где раздел вынесен в отдельную колонку, поэтому пункты можно корректно фильтровать и сортировать без объединённых ячеек.

На обоих листах задаются перенос текста, вертикальное выравнивание, осмысленные ширины колонок и границы. На листе `Данные` закрепляется строка заголовка и включается автофильтр. Числа и даты сохраняются типизированными значениями, а не имитацией форматированного текста.

## Поток данных и совместимость

При обычном формировании репозиторий копирует `scope` и `header_json` шаблона в запись чек-листа. При ИИ-формировании записывается шапка уровня филиала. Инициализатор базы добавляет новые колонки через идемпотентные `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, поэтому существующие установки обновляются без отдельного ручного шага.

Endpoint `/exports/checklists/{id}.{format}` и текущие кнопки остаются без изменения. Неподдерживаемый формат возвращает `400`, отсутствующий чек-лист — `404`. Ошибка генерации не должна возвращать частично сформированный файл.

Экспорт разрешён для черновиков и утверждённых чек-листов. Черновик имеет явную отметку «Не утверждён», утверждённый документ содержит дату и пользователя утверждения.

## Проверка

Автоматические тесты должны проверять:

- выбор шапки Общества и филиала;
- резервную шапку для ИИ- и старых чек-листов;
- неизменность снимка после редактирования шаблона;
- наличие всех значений пункта во всех трёх форматах;
- сохранение кириллицы;
- экранирование специальных символов;
- корректность ZIP-пакетов DOCX и XLSX и обязательных частей Open XML;
- повторяемую строку заголовка DOCX;
- печатный лист, нормализованный лист данных, фильтр, закрепление области и параметры печати XLSX;
- корректный заголовок и многостраничность PDF;
- отсутствие обрезания длинного чек-листа;
- имена файлов и MIME-типы.

Дополнительно создаются репрезентативные файлы с обеими шапками и длинными значениями. DOCX, XLSX и PDF открываются, визуализируются и просматриваются постранично. Проверяются кириллица, переносы, границы, повтор заголовков, отсутствие наложений и пригодность для чёрно-белой печати.

## Критерии готовности

- Все три кнопки скачивают открываемые файлы с фактическими значениями сформированного чек-листа.
- Шапка и завершающий блок соответствуют уровню Общества или филиала.
- Русский текст отображается без транслитерации и повреждённых символов.
- Длинные пункты и многостраничные чек-листы не обрезаются.
- DOCX можно редактировать в Word, XLSX — фильтровать и печатать в Excel, PDF — печатать на A4.
- При чёрно-белой печати сохраняются иерархия, границы и читаемость.
- Существующие URL и основной сценарий формирования чек-листа не меняются.
