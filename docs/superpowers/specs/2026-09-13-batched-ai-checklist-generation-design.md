# Пакетное ИИ-формирование чек-листа

## Проблема

Текущий экспериментальный сценарий дважды выполняет один и тот же набор из восьми последовательных RAG-поисков: при просмотре оснований и повторно при формировании. В production-логе каждый поиск занимает 6–10 секунд. После повторного поиска до 32 фрагментов отправляются в одном запросе Amvera/Qwen, который не успевает завершиться за 60-секундный таймаут.

## Цель

Исключить повторный поиск, ограничить каждый вызов LLM небольшим контекстом, сохранять прогресс между запросами и показывать пользователю проверяемые операции агента. Итог должен по-прежнему создаваться только после полной проверки и попадать в существующий жизненный цикл черновика.

## Поток

1. Анализ карточки остаётся отдельным шагом.
2. Поиск создаёт в PostgreSQL запуск `ai_checklist_run`, сохраняет снимок карточки, найденные фрагменты и план тематических пакетов. Повторного поиска на этапе формирования нет.
3. Интерфейс показывает сохранённые источники и будущие пакеты.
4. Браузер ставит пакеты в серверную очередь. Два фоновых worker-процесса обрабатывают очередь независимо от HTTP-запроса. Каждый пакет содержит не более пяти источников и не более 9 000 символов контекста. Один ответ содержит не более 20 пунктов.
5. Каждый пакет идемпотентен: завершённый возвращает сохранённый результат, упавший можно повторить отдельно. Состояния: `pending`, `queued`, `running`, `completed`, `failed`.
6. После завершения всех пакетов сервер повторно проверяет цитаты, удаляет дубли, ограничивает итог 100 пунктами и одной транзакцией создаёт обычный черновик.
7. Ограничения по времени выполнения и сроку жизни активного запуска нет. После перезапуска приложения пакеты в `running` возвращаются в очередь и продолжаются.

## Хранение

Отдельный инициализатор создаёт:

- `app_ai_checklist_runs`: идентификатор, объект, снимок профиля JSONB, статус, название, даты создания/обновления и идентификатор созданного чек-листа;
- `app_ai_checklist_evidence`: глобальный ID источника внутри запуска, тема, документ, раздел, текст, score и позиция;
- `app_ai_checklist_batches`: индекс и название темы, массив ID источников, статус, проверенные пункты JSONB, ошибка, длительность и даты.

Операции используют блокировки строк. Одновременно один пакет выполняется один раз. Финализация разрешена только при завершении всех пакетов и возвращает уже созданный чек-лист при повторном вызове.

## API

- `POST /api/ai-checklists/analyze` — анализ карточки;
- `POST /api/ai-checklists/runs` — единичный поиск, сохранение запуска и возврат источников с пакетами;
- `GET /api/ai-checklists/runs/{runId}` — восстановление состояния интерфейса;
- `POST /api/ai-checklists/runs/{runId}/batches/{batchIndex}` — постановка или повтор одного пакета в очереди;
- `POST /api/ai-checklists/runs/{runId}/finalize` — проверка общего результата и создание черновика.

`GET` состояния используется страницей для polling до завершения очереди. Старые `/search` и `/generate` остаются доступными на время совместимости, но новый интерфейс их не вызывает.

## LLM и проверка

Каждый запрос получает минимальный профиль без контактов и адреса, только свой набор источников и глобальные `S1…Sn`. Ответ использует существующую схему точных цитат. Парсер подтверждает источник, точное вхождение цитаты и тематическое покрытие заголовка. Пункты пакета сохраняются только после этой проверки.

## Информативная анимация

Интерфейс не показывает скрытые рассуждения модели. Он отображает фактическую телеметрию:

- подготовка тем и сохранение источников;
- очередь тематических пакетов;
- текущая операция каждого worker: отправка контекста, ожидание модели, проверка цитат, сохранение результата;
- количество источников и полученных пунктов, прошедшее время;
- завершение, ошибка и кнопка повтора конкретного пакета;
- финальные операции объединения, удаления дублей и сохранения черновика.

Для активных операций используются мягкая пульсация, движущийся progress bar, счётчик прошедшего времени без предельного срока и последовательный журнал событий. Учитывается `prefers-reduced-motion`; состояние и результат доступны текстом и через `aria-live`.

У именованного HTTP-клиента Amvera отключён общий таймаут. Отмена отдельного браузерного HTTP-запроса не отменяет уже поставленную фоновую работу.

## Ошибки и наблюдаемость

Сервер логирует `runId`, `batchIndex`, число и суммарный размер источников, длительность поиска/LLM/проверки, HTTP-статус провайдера и число принятых пунктов. Тексты источников, карточка и токен в лог не попадают. Ошибка одного пакета не удаляет результаты остальных и не создаёт частичный чек-лист.
