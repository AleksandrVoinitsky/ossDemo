# Экспериментальное ИИ-формирование чек-листа

## Цель

Добавить отдельный экспериментальный сценарий формирования рабочего чек-листа по карточке объекта и проиндексированной базе знаний. Существующий мастер `/Checklists/New` сохраняется без изменений.

## Пользовательский сценарий

В боковом меню появляется пункт «ИИ-формирование», ведущий на `/Checklists/AiNew`. На странице пять этапов:

1. Выбор объекта из реестра PostgreSQL.
2. Просмотр полей карточки, которые будут использованы агентом.
3. Запуск гибридного поиска по базе знаний и просмотр найденных подтверждений.
4. Синтез пунктов отдельным ИИ-агентом.
5. Сохранение результата как обычного черновика и переход в существующий экран проверки.

Из карточки объекта можно открыть этот мастер с уже выбранным объектом. Пользовательские результаты, утверждение, история и экспорт остаются в существующем контуре чек-листов.

## Архитектура

`AiChecklistQueryPlanner` строит ограниченный набор поисковых направлений из категории НВОС, типа объекта, региона, экологических аспектов, оборудования, источников выбросов, зон и разрешительной документации. Пустые и повторяющиеся признаки отбрасываются.

`IAiChecklistKnowledgeSearch` отделяет агент от конкретного RAG-движка. Runtime-адаптер вызывает существующий `RagService.SearchAsync`, то есть использует pgvector, Lucene.NET и локальный reranker. Результаты нескольких запросов объединяются и дедуплицируются.

`IAiChecklistSynthesisClient` получает карточку и подтверждённые фрагменты. Runtime-клиент вызывает существующий OpenAI-совместимый endpoint Amvera/Qwen с низкой температурой и требует JSON. Документы объявляются недоверенными данными; инструкции внутри них нельзя выполнять.

`AiChecklistAgent` проверяет ответ: название и основание обязательны, каждый пункт должен ссылаться только на известные идентификаторы источников, неподтверждённые пункты удаляются, дубликаты объединяются. При отсутствии источников или валидных пунктов черновик не создаётся.

## Хранение

Новый черновик сохраняется в существующих таблицах `app_checklists` и `app_checklist_items`:

- `template_id = NULL`;
- `template_name = 'ИИ · карточка объекта'`;
- `origin = 'ai'`;
- `basis` содержит документ и раздел источника;
- `note` содержит объяснение включения и уверенность.

Черновик независим от последующих изменений карточки и базы знаний. Утверждение разрешено только после заполнения результатов всех пунктов и переводит запись в неизменяемую историю.

## API

- `POST /api/ai-checklists/analyze` принимает `facilitySlug`, возвращает карточку и поисковые направления.
- `POST /api/ai-checklists/search` выполняет реальные RAG-запросы и возвращает дедуплицированные источники.
- `POST /api/ai-checklists/generate` повторно загружает карточку и выполняет поиск на сервере, синтезирует пункты, сохраняет черновик и возвращает его.

Клиентские источники не принимаются endpoint генерации, чтобы пользователь не мог подменить подтверждения между этапами.

## Ограничения

- Не более 8 поисковых запросов, 8 финальных совпадений на запрос и 32 уникальных фрагментов в контексте синтеза.
- Не более 100 итоговых пунктов.
- При недоступности БД, RAG или inference API показывается ошибка текущего этапа; частичный черновик не сохраняется.
- Эксперимент не изменяет существующий мастер, шаблоны и их API.

## Проверка

Доменные тесты проверяют построение запросов, дедупликацию источников, отклонение неподтверждённых пунктов, успешное создание черновика и отсутствие сохранения при ошибке. Дополнительно выполняются сборка решения, существующие checklist/RAG-тесты и синтаксическая проверка JavaScript.
